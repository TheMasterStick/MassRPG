Identity

Design notes

This is deliberately broad. You can design an NPC, quest, shop, book, title, transport route, service, loot table, dungeon concept or a system we have not even named yet. If it later affects live simulation, we promote it to a typed schema without changing its permanent ID.

Optional structured gameplay data

Template keys are drafting aids, not final runtime contracts. Use them to organize ideas; a runtime-relevant definition still gets a dedicated typed schema before live publication.

Presentation / assets

No Unity or Blender access is required here. Leave art IDs blank and use Needs assets; the entry will appear in the Asset Backlog when we are back at the home development machine.

Generic definitions are reviewable design records, but the live publication gate intentionally blocks them until runtime-relevant entries have been promoted to typed content.
